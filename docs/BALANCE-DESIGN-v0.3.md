# SmartApps Biz Game v0.3 バランス改訂設計

検証日：2026年10月25日。推奨候補：W1。対象は高校1年生20〜30人・50分・3ラウンド。

**この設計をゲーム本体v0.3へ反映しました。新規ゲームは改訂ルール、参加コードは3桁です。旧版の保存ゲームは旧ルールを維持します。**

## 結論

v0.2のPaid偏重とFree・Freemiumのほぼ恒常的な赤字を改善しました。改訂案は、広告収入と稼ぎ方を見直し、顧客を3種類に分け、開発・広告と市場集中の追加効果を逓減させます。勝率を同じにすることや、すべての選択で黒字になることを目標にはしません。

44候補を校正・比較した後、W1を固定し、新しい乱数系列で旧版と比較しました。最終検証は各人数5,000試行。以下の数値は、定めたランダム選択分布に対する結果で、プレイヤーの実際の勝率ではありません。

## 1. 旧新版を同じ選択で比較

| 社数 | 旧版：会社単位の赤字率 | 改訂案：会社単位の赤字率 | 改訂案：全社赤字となる試行 |
| --- | ---: | ---: | ---: |
| 2社 | 77.8% | 35.0% | 11.4% |
| 20社 | 92.4% | 26.5% | 0.0% |
| 30社 | 93.7% | 25.7% | 0.0% |

30社の場合のモデル別内訳：

| モデル | 旧版の赤字率 | 改訂案の赤字率 | 旧版の首位割合 | 改訂案の首位割合 |
| --- | ---: | ---: | ---: | ---: |
| free | 99.9% | 14.7% | 5.4% | 10.9% |
| freemium | 99.8% | 29.3% | 3.5% | 40.9% |
| paid | 81.5% | 33.0% | 91.1% | 48.2% |

同率首位は首位人数で等分して集計しています。Freeにも勝ち筋が生まれましたが、30社の首位割合は他2モデルより低めです。一方でFreeは赤字率が最も低く、「低めの利益で安定しやすい」という位置づけになっています。

## 2. 維持する基本ルール

- 最大30社、3ラウンド。全社確定後、運営管理者が集計。
- iOS配分0〜100%、Androidは残り。3モデルは毎回自由に変更可能。
- 販売・課金価格300／500／700円。Freeは0円。開発・広告はそれぞれ0／50／100万円。
- 参加社数×6,000人、各OSに半分ずつ。人数は3回とも固定。
- 基本運営費50万円。利用者1人につき変動費100円。投資はその回の全額費用で、その回だけ効果を持つ。
- 税、借入、資金制約、倒産、無形資産、品質の持越しは扱わない。
- 累計利益で順位を決め、同額は同順位。

## 3. 稼ぎ方を修正する

1ラウンドは仮想的な半年とします。広告収入は半年の利用を通じた1人あたりの合計という仮定で、実測値ではありません。

| モデル | 売上の計算 | 500円を選んだときの利用者1人あたり売上 |
| --- | --- | ---: |
| Free | 利用者数 × 広告収入400円 | 400円 |
| Freemium | 利用者数 × (課金率40% × 課金価格 ＋ 非課金率60% × 広告収入400円) | 440円 |
| Paid | 利用者数 × 販売価格 | 500円 |

Freemiumの課金利用者は広告なし、無料利用者は広告ありと仮定します。課金率40%は期待値として扱い、課金人数は丸めません。広告収入と、自社が集客のために払う広告投資は別のものです。

Freemiumの1人あたり売上は300円課金で360円、500円課金で440円、700円課金で520円です。低価格ほど選ばれやすい効果があるため、高価格が常に有利にはなりません。

### 同じ6,000人・開発と広告各50万円で手計算

全社が同じモデル・価格・50%配分・同額投資の場合を想定しています。異なるモデルが混在すると獲得人数も変わります。

| モデル | 売上 | 費用 | 利益 | 損益分岐点の人数 |
| --- | ---: | ---: | ---: | ---: |
| Free | 240万円 | 210万円 | 30万円 | 5,000人 |
| Freemium・500円 | 264万円 | 210万円 | 54万円 | 4,412人 |
| Paid・500円 | 300万円 | 210万円 | 90万円 | 3,750人 |

画像の例と同じ6,094人・固定費200万円・Freemium500円と仮定すれば、利益は71,960円、分岐点は5,883人です。**これは同じ人数での損益比較であり、新モデルでその人数を獲得できる保証ではありません。**

## 4. 顧客は3種類に分ける

プレイヤーの入力項目は増やさず、各OSの顧客構成を公開します。市場差は下表の顧客構成で表現し、OSごとに別の不透明な補正を重ねません。

| 顧客タイプ | Android内の割合 | iOS内の割合 |
| --- | ---: | ---: |
| 無料・低価格を重視 | 50% | 25% |
| 機能と価格のバランスを重視 | 35% | 35% |
| 品質を重視 | 15% | 40% |

モデル別の選ばれやすさ：

| 顧客タイプ | Free | Freemium | Paid |
| --- | ---: | ---: | ---: |
| 無料・低価格 | 3.0 | 1.2 | 0.3 |
| バランス | 0.85 | 2.0 | 1.0 |
| 品質 | 0.3 | 1.0 | 2.4 |

販売・課金価格による選ばれやすさ。Freeは常に1です。Paid・Freemiumには同じ表を使います。

| 顧客タイプ | 300円 | 500円 | 700円 |
| --- | ---: | ---: | ---: |
| 無料・低価格 | 1.8 | 0.7 | 0.12 |
| バランス | 1.25 | 1.0 | 0.4 |
| 品質 | 1.05 | 1.0 | 0.7 |

これらは授業用の人工的な仮定で、現実の利用者をこの3種類に断定するものではありません。Freemiumの課金価格がアプリ全体の選ばれやすさにも影響する単純化をしています。

## 5. 投資と集中に逓減効果を設ける

| 投資額 | 効果計算用の水準L |
| --- | ---: |
| 0円 | 0 |
| 50万円 | 1 |
| 100万円 | 1.35 |

最初の50万円による改善を1とすると、追加50万円による改善は0.35です。費用は追加50万円を全額払います。

開発係数は、無料・低価格タイプ0.25、バランスタイプ0.65、品質タイプ1.2。広告係数は全タイプで0.5です。

市場に割く割合x（0〜1）による競争力は `x^0.7` とします。50%配分は単独市場への全投入時の約61.6%の到達力です。両市場に分ける初期の効果が比較的大きく、集中をさらに増やす追加効果が小さくなる仮定です。**スライダーは労力配分であり、獲得人数や魅力度の直接比率ではありません。**

この追加仮定を採らず線形xにした候補V11は、一斉最適化で30社の第2回赤字率が87.8%になりました。配分の逓減を採用した理由です。

### 会社ごと・OSごと・顧客タイプごとの魅力度

```text
魅力度 = 市場への配分率^0.7
       × モデル別の選ばれやすさ
       × 価格による選ばれやすさ
       × (1 + 顧客タイプの開発係数 × 開発水準L)
       × (1 + 0.5 × 広告水準L)
```

各OS・顧客タイプの人数を、その組の全社の魅力度に比例して配分します。計6組の人数を会社ごとに合計します。配分0%の市場は対象外です。誰も参入しない市場の利用者は獲得されません。整数切捨て後の端数は小数部分の大きい会社から配り、同率なら登録順です。乱数はゲームの配分計算に使いません。

```text
固定費 = 50万円 + 開発投資 + 広告投資
変動費 = 利用者数 × 100円
利益 = 売上 - 固定費 - 変動費
損益分岐点人数 = ceil(固定費 / (1人あたり売上 - 100円))
```

## 6. 競合に対する戦略の探索

モデル→価格→開発→広告→市場配分の組合せを比較しました。通常のランダム試験は市場配分を0／25／50／75／100%の5点に限定し315戦略。追加の探索では0〜100%の全101点、6,363戦略を比較しました。

以下は各人数100種類の相手構成に対し、相手の選択を固定したまま1社だけ変更した場合に利益最大となった戦略です。全ての競争環境や均衡を網羅したものではなく、丸め前の期待人数で探索しています。

| 社数 | Freeが最大 | Freemiumが最大 | Paidが最大 |
| --- | ---: | ---: | ---: |
| 2社 | 0件 | 33件 | 67件 |
| 20社 | 20件 | 27件 | 53件 |
| 30社 | 25件 | 21件 | 54件 |

20・30社では3モデルすべてが利益最大となる状況が見つかりました。300／500／700円の各価格にも最大となる状況がありましたが、300円は主にFreemiumの低価格戦略です。すべての価格が全モデル・全人数で同じように有効とは主張しません。

開発100万円も50万円も有効な場面があり、広告は50万円が多いものの100万円が有効な場面も確認しました。0円は初回のランダム相手に対する最大解にはなりにくい一方、次節の3回目など、競合が変化した環境では多数選択されます。

2社ではFreeはこの最大解探索で選ばれませんでした。小人数では相手のいない領域を高単価で取れるため、20〜30社の本番のモデル間バランスを2社だけで判断しないでください。2社の試運転は入力・集計と手計算の確認用とし、戦略確認には20社の仮想競合を置く練習モードを次の実装候補とします。

## 7. 3ラウンドでの変更を検証

### 全項目を同時に最適化する厳しいストレス試験

全社が「他社は前回の選択を続ける」と予測して自社利益を最大にする選択へ同時変更します。各人数500ゲーム。プレイヤーの学習行動の予測ではなく、集中や振動を検出するための強い仮定です。

| 社数 | 第1回赤字率 | 第2回赤字率 | 第3回赤字率 |
| --- | ---: | ---: | ---: |
| 2社 | 33.5% | 0.0% | 0.0% |
| 20社 | 25.9% | 10.6% | 5.2% |
| 30社 | 25.2% | 8.7% | 41.8% |

W1では線形配分案の極端な第2回赤字集中を抑えられました。ただし30社の第3回は約42%が赤字となり、模倣・一斉移動による振れは残ります。「前回の勝ち方を真似すれば成功する」とは教えません。平均利益が黒字でも個別企業には大きな赤字があり得ます。

### 変更を一つに絞る比較試験

1回につき変更する戦略項目を最大1つとする探索も比較しました。モデル切替に伴う価格設定はモデル変更の一部とみなします。これは授業での考え方の比較で、アプリの入力制限としては設けません。各人数500ゲーム。

| 社数 | 第1回赤字率 | 第2回赤字率 | 第3回赤字率 | 3回累計が赤字の会社 |
| --- | ---: | ---: | ---: | ---: |
| 20社 | 26.5% | 15.9% | 12.2% | 11.8% |
| 30社 | 26.5% | 18.5% | 16.0% | 13.6% |

この2つの変更試験はseedも異なるため、差の全てを「変更項目数だけの因果効果」とは解釈しません。仮説を一つに絞って結果を説明する授業進行と相性がよいことを示す参考試算です。

## 8. 偏った市場構成での確認

30社・各構成1,000試行。3モデルが同数の場合だけに合わせた調整でないことを確認しました。

| Free / Freemium / Paidの選択確率 | 全体赤字率 | Free首位 | Freemium首位 | Paid首位 |
| --- | ---: | ---: | ---: | ---: |
| 70% / 15% / 15% | 24.8% | 0.2% | 18.4% | 81.4% |
| 15% / 70% / 15% | 30.0% | 10.7% | 62.7% | 26.6% |
| 15% / 15% / 70% | 31.8% | 71.8% | 27.2% | 1.0% |

同じモデルへの集中時は、少数派モデルが勝つケースが増えます。一方で、どの少数派でも必ず有利になるわけではありません。

## 9. 画面と授業の設計

- 確定前：1人あたり売上、固定費、分岐点に加え、「全社が同条件で6,000人ずつ獲得した場合」の利益を表示。売上予測の保証としては扱わない。
- 分岐点が総市場人数を超える場合は「この人数規模では黒字化できない条件」と明示。単純な赤字警告だけにしない。
- Free／Freemiumの説明に広告収入を明記。広告投資と受取広告収入を別欄にする。
- 結果は課金収入・広告収入・変動費・固定費を分けて表示する。
- 比較画面で市場別・顧客タイプ別の獲得人数を開けるようにする。通常画面では合計を優先し、グラフは追加しない。
- 第2回前に「何を一つ変えるか」、第3回前に「他社も動くならどうするか」を問う。入力自体は自由。
- 勝敗は累計利益。最後に品質・顧客満足・信用・人材など、利益だけでは測れない点を振り返る。

## 10. 検証条件と採否

### 試験分布

ランダム試験は各モデルを1/3で選び、そのモデルで使える価格を一様選択し、開発・広告各3水準、市場配分5点を一様選択します。旧新版に同じ選択を与えています。最終検証seedは845202（2社）、845220（20社）、845230（30社）で各5,000試行。各版計15,000試行・260,000社分の1ラウンド結果です。

44候補×20社×1,000試行の校正に加え、構成偏りのスクリーニング、1社変更の最大解探索、3ラウンドの変更試験を実施。候補の選定に使ったスクリーニングと、候補固定後の最終検証は分けています。

基準は実際の市場への統計的な妥当性を証明するものではなく、授業用プロトタイプの設計判断です。最終検証後はパラメータを再調整していません。

| 確認基準 | 結果 |
| --- | --- |
| 20・30社の一斉変更ストレスで各回の赤字率50%未満 | 確認 |
| 20・30社の追加探索で3モデルすべてに最大解がある | 確認 |
| 30社ランダム試験の全体赤字率50%未満 | 確認 |
| 20・30社の各モデルの首位割合10%超 | 確認 |
| 20・30社の単一モデルの首位割合70%未満 | 確認 |
| 20・30社の各モデルで過半数が黒字 | 確認 |
| 2・20・30社の全社同条件の標準選択で3モデルとも黒字 | 確認 |
| 20・30社の探索で300・500・700円の最大解がある | 確認 |

計算・人数保存・手計算例・分岐点の8件の自動テストも成功しています。

**採用判断：W1をゲーム本体に実装済みです。授業前には20〜30社を含む運営管理者の試遊で、選択理由を説明できるかを確認してください。**

留保：モデル別勝率の完全な一致、任意の相手に対する最適性、長期の均衡、全企業の黒字、実際のプレイヤーの行動や授業効果は保証していません。2社の最適解ではFreeが弱く、30社でも一斉変更時の利益の振れが残ります。

## 11. 再現方法と集計ファイル

```sh
node balance/simulate.js
node --test balance/model.test.js
```

追加ライブラリ不要、Node.js 22以上。詳しい実行方法は `balance/README.md`。`balance/results/final-validation.json` が旧新版の最終比較、`calibration.json` が44候補、`screening.json` が構成偏り、`fine-response.json` が1%刻みの探索、`adaptive.json` と `one-change-adaptive.json` が3ラウンド試験です。

線形配分の見送り候補は `node balance/simulate.js --candidate=V11` で別フォルダに再集計できます。`rejected-linear-effort.json` に選定時の集中ストレスの記録も残しています。

既存のゲームや授業データを変更せず、この設計検証だけを独立に再実行できます。
