# SmartApps Biz Game v0.5 試行バランス

2026年10月26日。最大15社で検証し、午後の実施に向けた試行版として選定。実際の参加者の行動予測ではありません。

## 採用設定

|項目|v0.4|v0.5|
|---|---:|---:|
|Freemium課金率|40％|30％|
|広告収入 対象利用者1人あたり|400円|300円|
|基本運営費 各回|50万円|30万円|

Freeの魅力度を旧版の1.8倍、Freemiumを1.4倍、Paidは1倍とする。これは人数の倍率ではなく、顧客配分前の獲得力への補正。Freemiumには価格係数の平方根を使い、一部課金なのにPaidと同じ強さで値上げを罰する問題を緩和。

開発・広告投資の選択肢、変動費100円、開発経験・生産性、移行費用、3ラウンド、累計利益による順位は維持。基本運営費の引き下げは全社共通なので、同じ意思決定に対する利益順位を変えず、1社あたり各回20万円だけ利益を増やす。

## 候補の選び方

広告収入250/275/300円、課金率10/20/30％、Free獲得力1.2/1.5/1.8倍、Freemium獲得力1/1.2/1.4倍、Freemium価格指数0.5/0.7を組み合わせた162候補。基本費50万円で、3/6/15社×各100ゲーム×3回を比較（48,600ゲーム）。

候補の評価値は、各モデルの勝者割合の1/3からの偏りの二乗和＋0.08×最大累計赤字率。均等な勝者割合だけでなく赤字も確認。候補を固定した後、基本費を共通で30万円に下げ、別seedで以下を検証。基本費を下げても勝者割合は変わらない。

## 別seedでの3ラウンド検証

各社は3回を通じて同じモデルを使い、価格・投資額は各回ランダム。市場配分は65％の確率で前回を維持。モデルの社数はほぼ同じにし、端数をゲームごとに回す。各社数につき新旧それぞれ1,500ゲーム。勝者割合は累計利益1位の会社が使っていたモデルの割合で、モデルごとの参加企業の勝率ではない。同順位は按分。

|社数|Freeが1位|Freemiumが1位|Paidが1位|Freeの累計赤字率|
|---:|---:|---:|---:|---:|
|3|29.9%|42.0%|28.1%|32.5%|
|6|33.6%|35.7%|30.8%|25.9%|
|10|35.5%|27.6%|36.9%|23.1%|
|15|33.1%|21.7%|45.2%|21.2%|

Freeが弱くなりすぎないラインとして、広告300円と獲得力1.8倍を組み合わせた設定を採用。課金率20％では、今回の候補ではPaid優勢やFreemiumの弱体化が出たため30％を選定。広告275円以下でも一部のFreeが勝つが、ランダム投資時の累計赤字が多かった。

## 3社の手計算ができる比較例

Free/Freemium/Paid各1社、全社Android50％・iOS50％、開発50万円、広告50万円、有料価格500円、初回。

|モデル|利用者数|今回の利益|
|---|---:|---:|
|Free|7,620人|224,000円|
|Freemium|6,258人|327,080円|
|Paid|4,122人|348,800円|

同じモデル・人数を与えた利益の保証ではない。Freeは人数が多い代わりに1人あたり売上が低い。Freemium500円の1人あたり売上は360円、Free300円、Paid500円。広告300円は最低課金価格300円を超えないため、課金率を下げたら売上が増えるという旧版300円Freemiumの逆転も解消。

## 適応と集中に関する追加試験と限界

全社が、他社は前回の選択を続けると仮定して当回利益を最大化する441戦略から同時に選び直す試験を、新旧各75ゲーム×4社数で実施。各戦略は配分0/10/25/50/75/90/100％、各モデル・価格・全投資を組み合わせる。評価値は小数人数、実際の集計は整数人数で、テストにより丸め差だけに収まることを確認。

この強い最適化仮定では3社でPaid優勢が残り、3回目のFree選択は0％、累計勝者はPaid約71％。6社以上ではFreeへの切り替えも起きるが、15社では全社の一斉変更による集中・振動が残る。完全な均衡、全社黒字、どのモデルも常に最適になることは保証しない。

さらに3社/15社で、特定モデルを選ぶ確率が80％（70％固定＋残り30％は3等分）になる各モデル偏重を、新版で各750ゲームずつ実施。全員に近い人数がFreeを選ぶと、無料市場での競争が激しくなり赤字が増える。無料モデルを無条件に救済するルールは設けない。

検証総数は候補選定48,600ゲーム、別seedの新旧比較12,000ゲーム、最適反応600ゲーム、偏重4,500ゲーム。いずれも最大15社・3ラウンド。実際の参加者の戦略や授業効果を実証したものではない。

## 再現方法

Node.js 22以上。追加依存なし。

```sh
node balance/v5-simulate.mjs screen
node balance/v5-simulate.mjs validate
node --test
```

候補選定はseed260101+社数、検証は761101+社数、最適反応は761201+社数、偏重は761301+社数。機械可読結果はbalance/results/v5/calibration.jsonとvalidation.json。

## 適用

本体は新規ゲームだけmodelVersion=5で保存。既存のv0.4/v0.3/v0.2を専用の旧計算関数に振り分け、過去結果と続行時の設定を保持する。画面表示の課金率・広告収入・基本運営費はゲームごとのrulesから取得。既存ゲームを続けるだけでは新バランスにならない。
