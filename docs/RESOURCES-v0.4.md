# v0.4 開発資源・生産性・市場移行の設計

2026年10月25日。v0.3のW1をベースに、開発資源だけを持ち越します。新規ゲームに適用し、既存のv0.2・v0.3ゲームは元の計算方式を維持します。

## 1. 開発投資を経営資源として持ち越す

各社にAndroid・iOSそれぞれの「開発資源」を内部的に保持します。初期値は0。開発ノウハウやコードの蓄積を表す投資換算の指標で、現金・会計上の資産額ではありません。投資は当回に全額を費用計上します。

```text
当回終了後の市場別資源
  = 当回開始時の資源 × 0.8 + 当回開発投資 × 当回の市場配分率
```

例：第1回で開発100万円・Android100%なら、次回開始時の資源はAndroid100万円・iOS0円です。第2回でiOS100%・開発50万円なら、第3回開始時はAndroid80万円・iOS50万円になります。

市場を移しても、元の市場の資源はすぐに失われません。元の市場へ戻れば残存資源を活用できます。資源が新しい市場へそのまま移ることはありません。

## 2. 翌回の生産性と既存品質に緩やかに効かせる

その市場の当回開始時資源をRとします。

```text
学習度k = R / (500,000 + R)
開発生産性 = 1 + 0.12 × k
既存品質効果 = 0.08 × k
有効開発水準 = 当回の開発投資水準L × 開発生産性 + 既存品質効果
```

投資水準Lは従来どおり0／50／100万円に対して0／1／1.35です。魅力度の開発部分を `1 + 顧客タイプの開発係数 × 有効開発水準` に置き換えます。それ以外の顧客構成・モデル係数・価格係数・配分率の0.7乗はv0.3と同じです。

過去資源が多い市場では、同じ当回投資でも少し高い効果を得ます。当回開発ゼロでも既存品質は少し残ります。生産性向上は理論上12%未満で飽和し、資源だけで勝敗を固定しにくくしています。

例：過去に両市場へ開発100万円を投じた会社と、開発ゼロの会社が、今回どちらも50%配分・Paid500円・開発広告各50万円を選ぶ比較では、利用者数は6,106人対5,894人となりました。これは一定の条件での例で、将来の顧客数を保証しません。前回の投資費用も含めれば、先行投資が必ず回収できるとは限りません。

## 3. 市場配分を変えると移行費用が発生

```text
市場移行費用 = 200,000円 × abs(当回iOS配分率 - 前回iOS配分率)
固定費 = 基本運営費50万円 + 当回開発投資 + 当回広告投資 + 市場移行費用
```

配分率は0〜1。100ポイントの変更は20万円、50ポイントは10万円、1ポイントは2,000円です。初回は移行費用0円。同じ配分を続ければ移行費用はかかりません。費用は固定費に一度だけ含め、利益と損益分岐点にも反映します。

資源の市場偏りによる生産性差と、移行作業に伴う当回の追加費用は別の効果です。切替の自由は残し、完全な切替禁止にはしません。

## 4. 広告はその回だけ

広告投資の水準は当回の魅力度にのみ作用し、開発資源にも次回の認知度にも蓄積しません。過去の広告だけを変更しても、当回の意思決定が同じなら当回の顧客配分・損益は変わりません。ただし過去の利益は累計利益に残ります。

## 5. プレイヤー・運営管理者の画面

- プレイヤー入口：`/`、`/index.html`、`/student.html`。ゲーム運営管理者の作成欄、ルール本文・ルールリンクを設けません。
- 運営管理者入口・管理画面：`/admin.html`。ルール本文、運営管理者の操作、全社の「未確定・考え中」「確定済み」のグループと人数を表示し、約3秒ごとに更新します。
- 新しい運営管理者ゲームの作成：`/admin.html?new=1`。既存の運営管理者画面の「入口に戻る」でも作成欄に戻れます。
- プレイヤーは開発資源額・生産性係数を見られません。プレイヤー用APIにも資源値・生産性係数・顧客タイプ内訳を含めません。
- プレイヤーには移行費用を確定前と結果で表示し、固定費・分岐点・利益との整合を保ちます。

この分離は授業用UIの構成です。本格的な運営管理者ログインや公開URLのアクセス制限は導入していません。運営管理者用URLや運営管理者向け説明ファイルをプレイヤーに配布しない運用を想定します。

## 6. 追加シミュレーション

2・20・30社について各1,000ゲーム、3ラウンドを実行。両版に同じランダム意思決定を与えています。初回はv0.3と同一、次回以降にのみ資源と移行費用が働きます。実際のプレイヤーの行動予測ではありません。

| 社数 | v0.3：3回累計赤字率 | v0.4：3回累計赤字率 | 人数変化の最大幅（対v0.3） |
| --- | ---: | ---: | ---: |
| 2社 | 23.6% | 27.5% | 4.3% |
| 20社 | 12.5% | 16.3% | 5.3% |
| 30社 | 12.0% | 15.8% | 5.4% |

移行費用の追加で、毎回市場をランダム変更する行動の利益は少し下がります。全社の黒字化を保証する調整ではありません。顧客獲得への影響は今回の試行で最大約5.4%に収まりましたが、これは試験中の観測値であり、任意の条件での上限保証ではありません。

再現方法：`node balance/resources-simulate.js` または `npm run simulate:resources`。結果は `balance/results/resources-v4.json`。関連テストは `test/resources.test.js` です。
